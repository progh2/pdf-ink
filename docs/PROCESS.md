# 필기웹 진행 방식

저장소: https://github.com/progh2/pdf-ink
팀장: 제타
역할: 기획, 디자인, 개발, 검수, 평가, 보안

## 마일스톤
- M1 기본필기: 업로드·렌더·펜·로컬저장·검증
- M2 툴바·획: 왼/오 겹침, 획 굵기, 슬롯
- M3 필기도구: 형광·팔레트·색연필·스탬프
- M4 편집기: 보기/편집·되돌리기·마스킹·영역캡처·전체화면·선택

## 규칙
1. 새 일은 이슈로 만든다. 이슈 없이 코드부터 쓰지 않는다.
2. 구현은 해당 이슈의 완료 기준만 맞춘다.
3. 진행 내용은 이슈 댓글과 이 문서에 남긴다.
4. 보안 담당은 방어적 수정만 한다. PoC·공격 절차는 쓰지 않는다.

## #284 미리보기 절반만 보이던 문제

세로로 긴 문서 미리보기가 절반만 표시되고 갱신이 안 되던 증상. 가상 스크롤(`previewRowStride`)은 모든 썸네일이 `--thumb-h`(고정 세로비) 높이라고 가정하는데, `.preview-thumb-wrap`이 `inline-block`이라 높이가 고정돼 있지 않아 가로가 긴 페이지(선반 붙여넣기로 섞인 개요 페이지 등) 썸네일이 더 짧게 렌더됐다. 그러면 실제 행 높이가 `rowBody`보다 작아지고 창의 `translateY(from × stride)`가 실제 위치와 어긋나 아래 행이 화면 밖으로 밀렸다. 썸네일을 `--thumb-w × --thumb-h` 고정 상자에 레터박스로 넣고 `.preview-row` 높이를 `calc(var(--thumb-h) + 50px)`로 고정해, 페이지 비율과 무관하게 모든 행이 정확히 한 stride 높이가 되도록 했다. 겸사겸사 import 누락으로 깨져 있던 capture.test.js `#253 배선` 블록도 고쳤다.

## #286 빠른 획 단순화 개선

빠르게 그으면 표본이 성겨 선이 단순화(모서리 둥글어짐)되던 문제. `ink.js` `tracePath`가 중점 통과 2차 곡선을 써서 실제 표본점이 곡선이 지나가는 점이 아니라 control point였다 — 성길수록 곡선이 실제 점에서 멀어졌다. 중심 파라미터(centripetal, α=0.5) Catmull-Rom 스플라인으로 바꿔 모든 표본점을 지나가게 했다(`catmullRomControls`). 부드러움은 유지하되 오버슈트/커스프는 없다. 이웃점이 겹치면(빠른 시작의 중복 표본 등) 균등 3차 fallback으로 NaN을 막는다. 1점(점)·2점(직선) 특례는 그대로.

## #288 폰·PC 선 두께 통일

같은 PDF라도 화면 넓은 PC는 페이지가 크게 표시돼 선이 상대적으로 얇아 보였다("PC가 얇아지네"). 두께가 CSS 픽셀 고정이라 페이지 표시 크기에 따라 페이지 대비 두께가 달라진 탓. 마스터 승인(폰 두께 기준)으로 획 두께를 페이지 기준으로 바꿨다: `lineWidth = width × canvas.width / STROKE_WIDTH_REF_CSS`(430). `canvas.width`만으로 정해져 본문·썸네일·굽기가 같은 규칙을 쓰고, 기기·DPR·확대와 무관하게 페이지 내용 대비 두께가 일정하다. REF는 폰의 페이지 표시폭 근처라 폰의 기존 느낌을 유지하고 PC가 그에 맞게 두꺼워진다. 도장·지우개는 CSS 기준 유지 — 지우개는 CSS 공간 히트테스트와 두께가 맞아야 하기 때문. REF는 한 상수라 "더/덜 두껍게"는 값만 조정하면 된다.
